## 8 Agent 设计与 Blueprint 承载

### 8.1 工作职责与阶段

Agent 服务六类意图：了解教学情况、核查具体问题、规划下一轮、准备材料、复盘、协调支持。PO 于 2026-10-18 已批准学情 Agent 给出重讲优先级和错因推测，逐条标为“AI 建议”并引用作答证据，由教师采纳、修改或否决；该决定覆盖本专项原先对 Phase 2 情境建议的限制，不再列为待定。首批申请 C01 查询、C02 看证据、C03 起草行动，先完成“有依据的建议→教师决定→行动和练习草稿”的价值链；后续执行、关联和复盘写入分批接入，不能用一句总结冒充业务完成。

| 来源与能力 | 可交付内容 |
| --- | --- |
| 学情 Agent 已批准的建议范围 | 在合格作答事实与授权范围内提供“AI 建议”：重讲优先级、错因推测；逐条关联人数、常见错选项或错答及典型作答引用，教师决定并可否决 |
| 教师主导的编排 | 检索已发布模板/资源，整理教师选择、AI 建议的采纳或修改、目标与约束；明确各内容来源 |
| 获准 Similarity Training | 按其正式合同提供巩固、变式等练习候选；不因本次建议放宽而提前或推迟开放 |
| 明确任务的材料生成/改题/组卷 | 复用各自已获准能力，包括 practice.draft.create 的实际业务编排；内容生成不冒充发布或任务执行 |
| Phase 3 Teaching Intelligence / Goal Planning | 承接本次局部放宽之外的正式情境教学策略、自动分组及跨目标规划等能力，按各自准入；不能反向将已批准的学情 AI 建议推迟到 Phase 3 |

本次调整基于教学价值：只复述错误比例会重复错题页，带证据的错因推测与重讲优先级能减少教师逐项查阅和组织判断的负担。相应代价是推测可能出错，因此把作答事实、AI 建议、教师决定和正式诊断分开；每条建议可追溯、可否决，不能仅靠“草稿”标签或教师最后点击掩盖越权执行。该放宽不创建或修改正式 LearningState、DiagnosisHypothesis，不更新 BKT，也不自动分组、承诺资源或代教师发布。

草稿区分教师原话/选择、模板引用、AI 建议、获准引擎候选和 Agent 整理。学情 AI 建议可以提出先重讲哪项及可能错因，无须先由教师给出该结论，也不以未激活 Teaching Intelligence 为前置；事实数字、比例和差距仍由确定性投影计算，模型不得补造。自动选择教学法、生成教学分组、跨目标价值排序等未在本次放宽内，不因模板白名单或建议标签开放；教师明确选择的模板、文字和获准内容候选仍可整理。该条按 PO 2026-10-18 V1 对原 Phase 2 限制作窄范围覆盖，并登记与 PTA、Agent 源文的同步修订；现有鉴权、来源资格、模型环境、HANDOFF 和业务 Admission 继续有效。

| 请求 | Agent 可做 | 仍须保留的边界 |
| --- | --- | --- |
| 解释错误 | 展示已有作答/评价事实，提出明确标注的 AI 错因推测，逐条引用常见错选项或错答、人数及典型作答 L0；列可见反例与未知 | 不把推测写成正式 DiagnosisHypothesis、稳定能力或人格结论，不更新 LearningState/BKT；教师可否决并保留记录 |
| 明天先重讲什么 | 提供带依据的 AI 重讲优先级，与错误影响范围等事实排序分别标明；教师可调整顺序或不重讲 | 不把 AI 顺序伪装成确定性指标，不替教师决定、执行或发布；本次批准不扩成任意教学法自动选择 |
| 准备练习 | 按教师选择提供“巩固练习”“错题变式”，复用 practice.draft.create 与全局题篮，保留题目精确版本和来源 | 选题、变式生成及保存分别依实际可用编排和 Admission；生成草稿不表示审核或发布完成 |
| 查看分组 | 展示教师选定成员，按其明确规则确定性筛选，或展示其他已获准引擎的实际候选 | 本次不开放学情 Agent 自动分组；不虚构批阅分组 owner |
| 支持与后续安排 | 整理教师已明确的需要和决定，形成可编辑行动草稿 | 不代负责人承诺资源，不将草稿显示为已安排、已执行或已发布；C04—C08 接入前不声称完成其业务写入 |

“AI 建议”是本专项已批准的应用建议，不是正式诊断。每条建议保存可重取的建议引用、生成版本及所用精确证据引用，记录教师采纳、修改或否决及时间；否决理由可选，不增加必填负担。该最少记录由工作台既有会话/草稿职责在首批承接，并随相应 schema 登记，不等待 C08，也不另建正式诊断或通用审核平台。查询及建议仍走 INPUT/result_ref；普通教师反馈保存为工作台输入/决定记录，不冒充领域 HANDOFF。保存业务行动草稿、练习草稿等外部副作用仍按对应写能力处理。重复同一 turn 回读原结果，不重推模型；显式刷新生成新建议时保留原教师决定，不把否决改成采纳。来源更正或撤权后保留允许的历史引用，阻断失效建议的新使用。

#### 学情 Agent 能力申请表

学情阶段首批申请 LA-C01、LA-C02、LA-C03，C04—C08 保留为后续能力，C09 报告快照与 C10 多角色请求继续另定范围。下表是能力申请设计，名称、handler、书面 owner 认可和字段合同须登记，不表示已经上线。应用 owner 指现有工作台应用职责的具名承接者，不新设 LearningAnalysis Domain Owner。C01 的建议生成作为其登记的分析输出处理，保留事实查询与生成版本的分别追溯；不把旧 NLU 的“只输出意图与参数”冒充已经支持教育建议，也不另外塞入未批准的多模型自主决策链。

C04—C08 不作为学情 Agent 首批入口或出口前置；独立页已经获准的行动与复盘功能继续按自身范围使用，不因 Agent 后置而关闭。C09 仅为报告快照申请候选，不包含本阶段报表重组，实际接入由 PO 另定；C10 属多角色后续。首批“巩固练习”“错题变式”复用 practice.draft.create：教师选择题目或获准目标、题量等条件，题篮提供同一全局数据源，生成只调用实际就绪的获准编排；练习保存走其独立 HANDOFF、原键查询与真实回执。C03 行动草稿不同时冒充练习产物或正式任务，两个 owner 的回执分别展示。practice.publish 仍是独立授权和明确确认后的操作，不能随采纳建议或生成练习自动执行。现有三项 P0 保持其实际 Admission 状态，未解除 CLOSED_TO_TRAFFIC 不接生产；页面不展示开发状态；设计画面以本地草稿状态及合成数据核对交互，真实回执分支留在实施验证中，不将本地响应写成业务成功。

#### 副作用 业务键和未知结果

下表为待 owner 认可的逻辑约束，不指定真实接口名或数据库字段。写能力的业务键由受信服务端为一次逻辑操作生成并固定，至少按组织和 owner 幂等范围隔离；请求摘要使用 owner 的既定算法。同键同载荷返回原结果，同键异载荷拒绝。不能用“内容 hash 一样”代替操作身份，也不能在超时后换键。

| 能力 | 副作用类别 | 业务幂等与目标约束建议 | 原键查询与未知回执 |
| --- | --- | --- | --- |
| LA-C01 | 只读 | 无业务写键；仅复用 INPUT/turn 去重与 result_ref | 重复输入回读原结果并重验权限；查询超时返回原因与显式刷新，不创建 HANDOFF/后台查询任务 |
| LA-C02 | 只读 | 无业务写键；INPUT/精确结果引用 | 同上；历史失权不因原引用仍在而放行；不以重新生成解释恢复读取 |
| LA-C03 | 创建个人应用业务草稿 | 固定逻辑创建键；同一 `org + origin_draft_ref` 唯一业务草稿；业务对象修订另用 CAS | HANDOFF 后按原键查真实草稿/终结；未知只核对原操作，禁止另造草稿绕开 |
| LA-C04 | 修改/安排/暂停/取消应用行动 | 每次教师明确操作固定键；行动 ID + 基准修订 CAS；保留原操作类型、受影响范围与部分执行 | 原键回读受理/正式结果/终结；未知不重新取消或改键重发；正式任务撤回须独立原领域回执 |
| LA-C05 | 追加执行事实或更正 | 固定逻辑报告键；明确原执行事件/报告引用，防同一事件重复导入；更正独立操作并关联前版 | 原键查询；未知不默认记执行成功，也不追加第二条事实；与系统事件冲突留待核实 |
| LA-C06 | 只读 | 无业务写键；INPUT/result_ref 与匹配规则版本 | 超时无后台造关联；显式刷新是新读取，原次仍可核查 |
| LA-C07 | 建立/撤销应用证据关联 | 固定操作键；同一行动轮次、观察精确引用、关系用途的有效关联唯一；撤销使用目标关联及基准修订 CAS | 原键查关联结果；未知不得重复链接/撤销，不复制正式 Evidence |
| LA-C08 | 保存复盘决定 | 固定提交键；复盘对象/基准修订 CAS，首次保存与 origin draft 唯一绑定 | 原键查复盘回执；未知不把行动显示已结束，不自动触发下一轮实例 |
| LA-C09 | 创建冻结报告 | 固定创建键；同一 origin report draft 只创建一次，其后修订显式另作操作 | 原键查 Report ID/版本；未知不另建报告；取得保存回执不等于已经共享/发布 |
| LA-C10 | 保存或交付协作请求 | 保存与外部交付按真实 owner 分开登记；外部发送若启用，固定请求/接收范围与同一 logical delivery 身份，禁止多次投递产生多请求 | 各操作原键查询；交付未知不能显示已发送，接收未知不能显示已接受；无恢复接口只允许未发送草案 |

所有写能力沿用既有预检→必要确认→本地原子 HANDOFF→owner 受理/提交→原键核定流程。普通可撤销个人草稿是否免确认逐能力判断；免确认仍不免 HANDOFF。必须登记受理窗口、同键查询、终结/迟到封闭、目标唯一或 CAS、取消语义、自动核定和本地人工核查出口；缺任何适用保证时该写能力不开放。未知不是失败也不是成功；“查无记录”本身不证明未来迟到请求不会生效。未决操作保留原键及合同恢复，不能用新草稿/新确认绕过。源读取或业务 owner 的真实回执不能由 LLM 文本代替。

两种来源策略均复用 v1.0，不新设 BOUNDED_PARTIAL_READ。策略和允许部分结果的含义随每项能力版本审批；页面不能降级。接受部分结果继续须能力允许且教师明确选择范围，标截止不能豁免门禁。上述都是申请草案，既有三项 P0 仍为 CLOSED_TO_TRAFFIC。

### 8.2 典型交互

从独立页进入时带可校验的范围、选中证据、结果版本、已有行动和来源页；直接输入时使用清楚可见的当前上下文，只有缺失会实质改变判断时追问。不能仅靠 URL 或自然语言授予权限。

接续读取、保存与交接时，服务端通过现有认证、权限适配和领域合同重验对象、用途、范围与精确版本；上下文 ID 仅定位，不授予访问。权限或版本变化按 §8.4 重新预检，不为本专项另建 scope token 或签名平台。依据：Agent §4.2、§5.3、§8.2。

教师问“明天二次函数哪些地方需要重讲”，Agent 在已校验的班级、学科、周期和范围内直接给出结果，无须教师先挑目标。事实列表默认沿用错题页错误影响范围降序：该题曾失分的去重学生数÷作答过该题的去重学生数；同值按题目引用 id、空值最后，每题显示分子分母，小分母不外推全班。每行同时呈现主要错误及人数、待订正/待再考、有有效预期依据时的与预期差距和一条典型错答 L0 引用。AI 可以据此提出重讲优先级与错因推测，逐条标“AI 建议”并点明证据；建议顺序与默认事实排序分别说明，不暗改指标排序。教师可采纳、修改、否决或暂不行动，决定是否重讲及先处理哪项；Agent 根据教师选择起草安排，并提供“巩固练习”“错题变式”和全局题篮入口。建议不写正式诊断或知识状态，不自动分组和发布。

题行预期差距逐题采用MET10相同来源优先规则并保留各项来源版本，表示该题实际得分率减该题预期率；MET10整次值仍须满分加权，不能平均显示差距。大号比例明确标“失分比例”，定义为该题曾失分的去重人数/作答过该题的去重人数，非丢失分值占比；人数分子分母与比例同现。学生进展状态只属于学生范围，不贴在题行；本版题行也不放掌握度，知识点视图如展示掌握度须明示知识点和相应学生/班级范围。常见错误人数与典型错答须来自可重取统计及作答，不能由错误率补造。

人数、比例、待办及差距来自结构化查询；语言模型可在已批准范围内给出带证据的建议，不能补算未登记指标或把错因推测改称事实。教师否决保留原建议、依据和决定；后续草稿采用教师当前选择，不反复恢复已否决内容。保存行动与练习分别显示真实回执和对象引用，尚未保存的页面只显示“草稿，未保存”。后续创建任务或发布分别授权，执行或结果事件到达才推进其状态。切换班级或会话不混入旧范围，返回保留草稿、选择和滚动。

采纳交互提供“采纳”“改后采纳”“暂不采纳”。直接采用AI内容的草稿字段标“来自AI建议”，教师基于该内容改写后标“由AI建议改写”，保留原建议/证据引用和编辑链；纯手工输入且未采用建议不附AI来源。教师未编辑的派生字段随决定变化更新或清空，已编辑字段保留原文，仅提示差异，由教师明确选择替换；取消修改不改决定。不同建议与字段分别追溯，已保存成果走修订流程，不被临时决定自动重写。暂不采纳仍可自行起草，不要求附已拒绝建议的引用。

**r2 补充交互约束：**已编辑字段遇到所采用建议或决定变化时，显示“建议已变化，你的内容未改动”，提供新旧内容核对、保留原文和显式替换；取消不改变内容，确认替换后字段内容及来源标记必须同时更新。教师可经明确确认将当前重写内容标为“教师自拟”；此操作只调整当前文字的可见来源声明，原建议引用、采用决定和编辑链仍保留。不能自动删掉引用，也不能仅凭当前采纳按钮状态重标旧文字来源。

桌面按 Blueprint §4.2、§15.3.1 的 1440×900、1280×720 基准验证；协作阈值看扣除导航和内边距后的净宽，至少 1016 CSS px 容纳 360 会话＋16 间距＋640 对象。不足时退出并排，恢复至少 1064（48 px 滞回），并尊重用户手动关闭状态，不把 1280 窗口一概判单栏。窄屏保留一个主要目标，退出可恢复。

本轮承接 PO 2026-10-17 决定：导航收起后隐藏窄栏，1280 宽扣左右共 48 px 内边距约为 **1232 px**，不再扣历史 56 px 轨；展开导航按实际占用测量。该点是对 Blueprint 快照算式的已明确产品调整，1016/1064 净宽阈值及 48 px 滞回不变；浏览器按 CSS 实测，不以窗口数字替代净宽。

同对象切换交接组织/职责/用途、班级、学科、周期、对象与精确版本以及决定数据集合的筛选条件，服务端重验；保留原页筛选、搜索、排序、缩放与编辑。目标界面不支持的展示状态留在来源页，不能悄悄改成另一查询。主动进入更宽总览时清楚显示新范围及未沿用条件，原草稿仍属于原对象。取消返回恢复仍有效的状态、位置和焦点；内容变化则定位稳定对象并说明，撤权缓存不恢复。

从“B 班周测第 5 题”选择继续当前分析，仍是该范围；主动打开“B 班总览”则使用总览明示范围，不暗带题级过滤。A 班目标 X 进入 Agent 后取消，回到 A/X 原草稿。AG01/AG06/T07 覆盖上述路径以及跨班、未支持筛选、未保存编辑、来源更正和撤权；P2 验页面与交接合同，P3 验真实双入口。

复用智能曜彩公开组件，以范围/质量摘要、证据卡、行动编辑、后续观察和执行确认为业务组合。轻量 Blueprint 使用细线、结构编号与柔和组件；颜色与文本/图标共同表达状态，不依赖颜色单独传递信息，不用装饰仪表盘伪造精确性。本专项默认验证 Blueprint v1.0 范围的 light、paper、dark 三核心主题及第四主题 blueprint。当前组件仓已注册并实现 blueprint-night；工作台接入及完整验收本轮未核实，是否纳入本专项另登记并补验证，不能据组件实现计作业务通过。

### 8.4 确认 回执与恢复

读取、筛选、确定性计算和合法草案整理不逐步弹确认。保存、创建任务、发布给学生、共享报告等副作用分别授权，确认中明确动作、对象、人数、范围、版本及后果；既有授权仍吻合时复用，实质变化时重新预检。

工作台在本地事务中原子消费确认并持久化 HANDOFF；领域 owner 在接受和提交时再核对权限、版本、质量与幂等。Agent 架构 P0 只读查询仅持久化 INPUT/result_ref，不为“查询中”伪建 HANDOFF 或后台任务。

| 异常 | 必须行为 |
| --- | --- |
| 无证据或仅部分 | 展示缺口；局部读取须合同允许且明确选定范围，不外推全班 |
| 来源更正/撤回/失效 | 保留历史并立即收回相应新用途资格；等合格新依据再继续 |
| 查询失败/超时 | 保留问题，用户显式刷新开新轮，不静默重试旧轮 |
| 写入结果未知 | 查原 HANDOFF 回执；只有合同允许且确认未生效后，才重新预检尝试，不盲重放 |
| 重复提交 | 幂等，不重复行动/试卷/任务 |
| 用户中止 | 区分已完成与未执行，恢复草稿，不自动续跑副作用 |
| 确认期间对象变化 | 原确认失效，展示差异后重新确认 |
| 权限/组织变化 | 阻止继续访问，不从缓存或对话泄漏旧明细 |
| 教师否决解释 | 保留事实与修订/否决，更新后续草案，不传播为确定结论 |

### 11.2 与 PTA 和 STEP1 的关系

| PTA 阶段 | 本专项可承接内容 | 不可替代的验收 |
| --- | --- | --- |
| Phase 1 | 合格证据呈现，配合 Similarity Training Experience；使用获准练习候选与静态目标 | Learning State（BKT）、Learning Diagnosis、Similarity Training 三引擎共同构成最低闭环；图表、人工行动或 P1 完成不等于完整 Phase 1 |
| Phase 2 | 教师读取状态/诊断/证据、查询资源及人工编排；学情 Agent 按 PO 2026-10-18 V1 已批准提供重讲优先级与错因推测 | 本次局部建议不再等待 Teaching Intelligence 激活；每条标 AI、引证据、可否决，不写 LearningState/DiagnosisHypothesis/BKT，不自动分组或代发布。其他情境策略能力、Similarity 与内容处理仍按各自范围和 Admission |
| Phase 3 | 获准 Teaching Intelligence、Goal Planning 等提供其正式候选 | 正式引擎、跨目标规划与本次学情局部建议分清；不能以 Phase 3 未到为由撤回已批准的 V1 价值，也不能将 V1 扩成任意教育决策或执行权 |

STEP1 沿 M0→M1→M2→M3A/M3B→M4 主线推进。静态题路径 M3B 可先承接后续任务，新题生成 M3A 不能成为所有教学行动前置。VVP-C 返回下一任务候选，仍须相应决定和确认成为实例。

管理能力还须逐项映射 Institutional Experience、组织和阶段门禁，不因 P4 排在后面就自动准入。当前文档基线记录 Agent 三项 P0 能力为 CLOSED_TO_TRAFFIC、生产 NO-GO；本稿不解除该状态，也未重新测试生产接口。设计批准、实现检查、浏览器、真实服务和教学验证分别记录。

未解除 CLOSED_TO_TRAFFIC 前，P3 可在受控环境做契约、夹具、适配及获准真实 owner 接入验证，生产流量由服务端能力目录、权限和准入状态阻断，覆盖查询及写回；前端 feature flag 不替代门禁。实接一致性、撤权、重复调用、未知结果和恢复分别留证，固定夹具通过不能记为真实服务已通过。依据：Agent §2.1、§12.2 与 STEP1 当前索引的 WB-Gate。

真实服务验证前置到最早依赖它的功能交付或试点：P0/P1/P2 若声称真实读取结果、保存行动或取得执行/复查回执，相应 owner 服务、授权、精确版本、失败与恢复必须实接通过，可使用获准测试数据。夹具与局部 UI 可先行并标明范围；不能等 P3 再补证此前已声称的真实业务。P3 增加 Agent 双入口和 HANDOFF 一致性，不替代领域服务验证。

既有 Agent 三项 P0 能力仍为 assessment.result.query、practice.draft.create、practice.publish；“查询/行动/复盘”只是产品意图，不重命名能力目录。独立页描述性结果与教学事实读取不新增 Teaching Graph 或 Teaching Intelligence 首版前置；正式诊断、策略分别过门禁。各项受控验证和生产开放按自身条件推进。

学情专项P0—P4、工作台Agent前端R1—R18、PTA Phase/STEP1 Gate为三条不同轴。体系首期保留批阅闭环及已有结果查询、个人练习草稿、单班首次发布的逐项接入；Blueprint首条前端链只到批阅解析→复核→保存确认→同版重开，明确不含发布。现行第二期R10—R18不含完整学情视图。

PO 于 2026-10-18 已决定在工作台 Agent 第二期 R18 之后单列“学情协同阶段”，不再作为待定项；具体轮次由工作台实施规划排定，本稿不编日期或新 R 编号。首批申请 LA-C01 查询与 AI 建议、LA-C02 证据核查、LA-C03 行动草稿，并复用已有 practice.draft.create 与全局题篮，完成“事实→AI 建议→教师决定→行动/练习草稿”。C04—C08 后续接入，C09 报告快照和 C10 多角色请求另定范围，不能前置阻断首批。阶段与建议权限已定，不等于接口已上线：能力登记、真实服务与 Admission 仍按各自首次实际依赖取得证据；整体v0.7设计批准见§13.7，真实接入及验收另行留证。
