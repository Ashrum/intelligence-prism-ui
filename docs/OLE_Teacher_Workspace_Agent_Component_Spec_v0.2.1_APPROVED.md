## 1. 目标

Teacher Workspace 不应退化为“聊天 + 表单”，也不应要求教师通过自然语言重新寻找所有高频业务入口。

Agent 理解意图并提出任务、参数或内容候选；Runtime 与受授权业务服务负责校验、编排和正式执行。界面在合适时机呈现结构化组件，让教师完成确认、选择、编辑、审核、执行与查看。在 Agent 对话、固定页面和任务工作区之间，复用同一业务对象及其权威版本，不形成两套业务实现。

系统内部可以复杂，但教师感知到的路径必须尽可能短。

> **能一点完成的，不要求教师说一句；能说一句完成的，不要求教师点十下；需要认真工作的，再进入 Workspace。**

## 2. 基线原则

### 2.1 一个任务，两种可支持的呈现方式

组件体系支持 **Inline（对话态）** 与 **Workspace（扩展态）**。每个语义组件按真实任务需要声明支持范围；可以只有 Inline，可以复用通用扩展容器，也可以同时提供两态。不能为了形式齐全而给简单组件增加空洞的独立 Workspace。

本规范第 6 节两列描述的是可承担的交互职责，不代表每一项都必须独立实现两个界面。只有确有扩展内容时，才提供展开入口；未实现的能力不得显示为可执行。

| 呈现方式 | 承担的工作 | 设计要求 |
|---|---|---|
| Inline｜对话态 | 信息摘要、关键参数确认、候选选择、轻量修改、预览与下一步决策 | 优先让当前决策在一屏内完成；不以隐藏关键证据、压缩文字或拆出大量卡片换取紧凑 |
| Workspace｜扩展态 | 完整配置、大规模选择、深度编辑、多步骤审核、分析与内容创作 | 保留对象、范围、版本和草稿；展开不重新填写；允许长时间驻留，能明确返回 Agent 或原固定页面 |

### 2.2 不建立第三种正式组件形态

后台运行、等待模型、协作、版本变化和错误等属于任务或交互状态，不构成第三态。手机、固定页面、分栏、抽屉、浮层和专注全区分别属于设备、入口或承载布局，也不新增业务呈现类型。

公共状态复用第 7 节能力；浮层或抽屉的使用不得复制业务对象或创建第二套执行逻辑。

### 2.3 权威数据、编辑草稿、视图状态与历史快照

> **Inline、Workspace 与固定页面引用同一业务对象及其权威版本，不得形成彼此独立、相互覆盖的业务副本。允许存在有明确归属与基准版本的编辑草稿，以及独立的视图状态和历史快照。**

| 状态类别 | 定义与边界 |
|---|---|
| 权威业务数据 | 由既有业务对象及其管理服务维护的正式版本与执行事实；组件不能自行将候选或本地修改提升为正式结果 |
| 编辑草稿 | 尚未正式提交的修改，关联编辑者、任务对象及基准版本；在不同入口展示同一草稿时不得另建相互覆盖的编辑副本 |
| 视图状态 | 展开、关闭、选中、滚动位置、专注模式等呈现信息；不改变任务归属、业务版本或执行状态 |
| 历史快照 | 记录当时版本、范围与操作事实的只读信息；不是当前可写业务副本，读取仍受当前权限限制 |

同一对象可以存在不同编辑者的显式草稿，但不得把未提交草稿当成同一份正式结果。关闭面板、返回对话和切换入口不等于提交、丢弃或取消任务；相关动作必须分别表达。

这些是职责划分，不要求新增统一大对象或用一个 `TaskSessionSchema` 替代既有任务、成果和版本契约。

## 3. 响应式与移动端能力适配

Mobile 不构成新的组件形态。适配包含 **布局适配** 与 **能力适配**，不等于只改 CSS，也不等于移动端统一只读。

### 3.1 布局适配

依据实际可用容器宽度、内容复杂度和操作方式，支持多栏转单栏、表格转分段列表、大型画布进入专注全区、次级操作收纳和主操作稳定可达。具体断点复用既有工作台骨架，不在本规范强制固定屏幕宽度或侧栏像素值。

必要的二维画布可以保留缩放与平移；标题、任务状态、工具栏和返回入口仍应可读、可达。不能把整页无法重排都归因于画布复杂。

### 3.2 能力适配

| 能力情况 | 移动端处理 |
|---|---|
| 可完整操作 | 重排交互，保留原业务能力 |
| 可通过等效操作完成 | 提供适合触控的替代方式，例如拖拽排序增加“上移／下移”，不只支持鼠标或悬停 |
| 只能可靠完成部分工作 | 显式声明可浏览、可批注或可轻量修改的范围；保留草稿和桌面接续入口，不伪装为完整编辑器 |
| 当前无法可靠支持 | 清楚说明不可执行的能力及接续方式，不制造成功提示或空的“完成”动作 |

几何作图、关系图、多级编排等重型组件应单独判定，不预设全部可用，也不预设全部只读。能力限制不改变任务对象、权限、正式提交条件或已保存事实。

### 3.3 窄屏任务连续性

允许在专注操作或紧凑试题篮中暂时隐藏对话，但必须让教师知道“正在处理什么、处于什么状态、修改是否保存、怎样返回”。应保留任务身份、重要状态变化提示和明确的 Agent 返回入口；恢复时保留对象、草稿与合理的阅读位置。

不得因隐藏对话而让运行中任务被误认为已完成，不得因打开新结果而强行替换正在编辑的内容。退出专注模式不等于撤销修改或取消执行。具体路径列入第 13 节待验证项目。

禁止为移动端复制一套业务逻辑、创建独立业务数据模型，或静默改变任务范围和结果语义。

## 4. Agent、固定页面与 Workspace 的关系

> **Agent 入口 + 固定业务入口，双入口、同任务、同组件、同权威数据。**

固定页面服务于高频访问、可发现性、历史回访、批量工作和长时间驻留。Agent 服务于目标表达、上下文理解、快捷启动与跨业务编排。固定入口可以直接调用既有组件和授权服务，不必先经过一次自然语言交互或模型调用。

教师说“打开昨天高二三班的数学作业”，或者从“批阅与解析”进入，应打开同一业务对象及其当前可访问版本；从历史入口查看时，应明确显示当时版本与当前版本的区别。

### 4.1 布局承载

Workspace 可以采用并排布局，也可以进入专注全区。具体选择由可用空间、任务复杂度和教师主动操作决定，不强制始终分屏，不强制居中模态框，不强制 `1440px + 400px Agent 侧栏`。

并排与全区是扩展态的布局变化，不是第三种组件形态。展开、缩放、关闭及对象／试题篮内容切换，应由既有工作台视图管理能力承担，而不是让每个业务组件另建一套外壳。

### 4.2 生命周期与接续

对话不必始终可见，但 Agent 必须可达。打开、收起、最大化和恢复只改变呈现；离开编辑前按第 8 节处理草稿，不能以返回按钮代替提交或丢弃确认。

Agent 的异步请求不得抢夺正在编辑的焦点、覆盖教师主动打开的内容，或重新弹出教师已明确关闭的同一请求。其他会话的迟到结果不得改变当前任务或界面；应回到其所属任务记录。

返回路径应恢复原入口的任务上下文，不重新询问已知信息，不自动把整个成果视为“已加入模型上下文”。

## 5. 组件分类总览

| 项目 | 本版口径 |
|---|---|
| 组件族 | **12 类**，维持 v0.2 分类 |
| 语义组件 | **42 个**，名称与数量不变 |
| 呈现方式 | **Inline / Workspace**，按组件需要声明支持范围 |
| 84 的含义 | 42 × 2 的理论覆盖组合数；不是必须实现的 84 个界面，不是页面数或代码包数 |
| 公共能力 | **4 项**：全局任务状态、历史与版本、协作、权限与数据范围 |
| 复合容器 | 属于组合与承载规则，不计入新增语义组件或第十三类 |

十二类是按主要交互职责组织的能力目录，不是十二个强制业务步骤，也不是严格互斥的任务阶段。归属规则见第 12 节。

组件数量描述能力边界，不意味着全部本期实现，也不意味着教师会同时看到这些组件。不得把完整能力目录直接等同于当前研发工作量。

## 6. 十二类 Agent 组件

以下保留原有 42 个语义组件。Inline／Workspace 两列为支持该呈现方式时的职责说明，不要求分别新建独立界面；具体支持范围、限制和可用性应明确声明。

### 6.1 范围与对象

用于明确“这次任务针对谁、什么内容、什么范围”。范围选择只确定任务涉及的对象集合，不授予访问权限；授权边界见第 7.4 节。

| 组件 | 核心职责 | Inline | Workspace |
|---|---|---|---|
| 对象选择器 | 班级、学生、教师、课程、任务等单一/少量对象选择 | 快速选择/确认 | 完整搜索、筛选、多选 |
| 范围构建器 | 年级、章节、知识点、学生群体、时间范围等组合范围 | 展示与微调核心范围 | 完整构建复杂范围 |
| 上下文摘要 | 汇总当前任务对象、来源、约束与上下文 | 一屏摘要 | 展开查看完整上下文与来源 |

---

### 6.2 输入与导入

用于将外部内容输入当前任务。

| 组件 | 核心职责 | Inline | Workspace |
|---|---|---|---|
| 文件输入 | PDF、Word、Excel、图片等文件上传与选择 | 拖入/选择少量文件 | 批量上传、队列、文件管理 |
| 采集扫描 | 试卷、作答、教材页、板书等拍摄/扫描 | 快速采集 | 批量扫描、页序、质量检查 |
| 内容输入 | 文本、Markdown、URL 摘录、粘贴内容等 | 轻量输入 | 长文本编辑与结构化输入 |

> 文件“上传”与文件“工作”必须区分。上传属于输入组件；真正阅读、编辑、生成和输出属于“内容与成果物”。

---

### 6.3 参数配置

用于明确任务执行规则与约束。范围构建器回答“哪些对象参与”；约束构建器回答“执行或结果必须满足哪些条件”，两者不互相替代。

| 组件 | 核心职责 | Inline | Workspace |
|---|---|---|---|
| 参数配置器 | 题量、时长、难度、评分方式等常规参数 | 关键参数 | 完整参数集 |
| 约束构建器 | 必须/禁止/比例/边界/规则等约束 | 查看并修改主要约束 | 复杂约束组合与冲突检查 |
| 模板选择器 | 试卷、作业、教学方案、分析模板等 | 推荐模板与快速切换 | 模板库、预览、管理与配置 |

---

### 6.4 选择与组合

用于从候选内容中选择并形成结构。

| 组件 | 核心职责 | Inline | Workspace |
|---|---|---|---|
| 候选选择器 | 题目、资源、知识点、学生等候选项选择 | 少量候选快速选择 | 大规模筛选、排序、批量选择 |
| 集合篮 | 暂存已选题目、素材、资源、学生等 | 数量与关键项摘要 | 完整集合管理 |
| 结构编排器 | 调整试卷、任务、课程、内容的结构与顺序 | 简单移动/确认 | 拖拽、分组、层级、批量编排 |

---

### 6.5 预览与查看

用于在执行或提交前理解当前结果。

| 组件 | 核心职责 | Inline | Workspace |
|---|---|---|---|
| 摘要预览 | 结果快速预览 | 关键结果卡片 | 完整摘要与细节 |
| 对象查看器 | 查看题目、作答、学生、任务、资源等对象 | 快速展开 | 完整对象详情 |
| 对比查看器 | 版本、答案、学生、方案、前后结果等比较 | 关键差异 | 并排/差异化完整比较 |

---

### 6.6 审核与修订

用于 Human-in-the-loop（人在回路）的人工复核。

| 组件 | 核心职责 | Inline | Workspace |
|---|---|---|---|
| 审核队列 | 待审核对象集合与优先级 | 待办摘要 | 批量审核工作区 |
| 单项复核器 | 对单题、单页、单条诊断等进行确认与修订 | 快速通过/修改 | 完整证据与编辑能力 |
| 异常处理器 | 低置信度、冲突、缺失、无法解析等异常 | 提醒与快速选择 | 原始材料、证据、规则与人工处置 |

---

### 6.7 分析与诊断

用于教师理解学习状态，而不是只输出图表。

| 组件 | 核心职责 | Inline | Workspace |
|---|---|---|---|
| 指标摘要 | 核心指标与显著变化 | KPI 与异常提示 | 指标体系、趋势与解释 |
| 分布矩阵 | 班级、知识点、能力、题型等二维/多维分布 | 关键区域摘要 | 热图、矩阵、筛选与比较 |
| 下钻与证据浏览 | 从诊断结论进入学生、题目、作答和证据 | 单一结论下钻 | 多层级诊断与证据链浏览 |

---

### 6.8 计划与建议

用于把分析转化为后续教学行动。

| 组件 | 核心职责 | Inline | Workspace |
|---|---|---|---|
| 建议集 | 教学建议、干预建议、学习建议 | 推荐项选择 | 批量比较、采纳、调整 |
| 计划构建器 | 教学计划、学习计划、复习计划、任务计划 | 核心步骤确认 | 时间线、任务、资源、对象完整编排 |
| 路径与优先级 | 学习路径、补弱顺序、任务优先级 | 下一步建议 | 完整路径图与人工调整 |

---

### 6.9 执行与追踪

用于真正把任务“做出去”。执行结果说明做成了什么、失败了什么；成果物输出负责格式、版式、范围和文件交付，两者可以组合。

| 组件 | 核心职责 | Inline | Workspace |
|---|---|---|---|
| 执行确认 | 发布、布置、生成、批阅、导出等最终确认 | 一键确认 + 风险摘要 | 完整执行参数与影响范围 |
| 任务进度 | 长任务与异步任务状态 | 紧凑进度 | 队列、阶段、异常、耗时与重试 |
| 执行结果 | 任务完成后的结果与后续动作 | 完成摘要 | 完整结果、日志、输出与继续操作 |

---

### 6.10 内容与成果物

该类不是简单“附件预览”，而是 OLE 承载、编辑、生成和交付内容的核心工作区。

| 组件 | 核心职责 | Inline | Workspace |
|---|---|---|---|
| 文档工作区 | Word、PDF、Markdown、富文本等阅读/编辑 | 文档摘要、节选、快速操作 | 完整阅读、编辑、批注、结构导航 |
| 演示文稿工作区 | PPT/Slide 类成果物 | 页缩略预览 | 页面编辑、排序、演示结构 |
| 图像查看与画布 | 图片、插图、截图、教学图像 | 图片预览 | 放大、标注、裁切、组合、编辑 |
| 音频与转写 | 听力材料、录音、语音、转写 | 播放与片段摘要 | 波形、分段、转写、时间轴编辑 |
| 视频与时间轴 | 教学视频、演示视频等 | 播放与关键片段 | 时间轴、章节、字幕、片段管理 |
| 成果物输出 | 将结果导出为用户需要的格式 | 快速导出 | 格式、版式、范围、版本与批量输出 |
| 图形关系工作区 | 流程图、思维导图、概念图、知识关系图 | 缩略图/关键节点 | 节点、连线、布局、属性、交互编辑 |
| 结构化内容工作区 | 大纲、树状内容、课程结构、章节结构 | 层级摘要 | 层级编辑、拖拽、折叠、结构调整 |

#### 格式与适配器边界

Word、PDF、Markdown、PPT、PNG、MP3、MP4 等是内容格式，由 Renderer / Adapter（渲染器／适配器）支持，不分别升级为新的组件类型。

统一资产身份、来源、版本、权限及能力声明；正文、幻灯片、关系图、音频和视频可以保留各自合适的内容模型，不强制全部转换为同一个 AST 或 Block JSON。共享元信息不等于共享一种编辑数据结构，也不要求新增 OLE 权威对象。

适配器应明确支持查看、编辑、批注、生成或导出的哪些能力，以及不支持项和有损转换风险。不能因为能够预览 PDF 就声称能够完整编辑，不能因为能够生成 PPT 内容就声称已生成可下载的演示文件。

组件负责承载与交付，具体能力可以复用既有工具或外部服务；本目录不等于本期自研 Office、图像、音频或视频编辑器的承诺。成果应保留任务、版本与来源关联，下载链接只能指向实际可用且当前有权访问的文件。

结构化图形保留节点和关系；导出为静态图片不等于原结构仍可编辑。第 6.12 节学科工具负责领域计算、约束和模拟，不因支持编辑节点就把通用图形工作区重新归类。

- 年级；
- 章节；
- 知识点；
- 教学目标。

用于承载“可操作、可计算、可模拟”的学科能力。

| 交互演示器 | 几何、语法结构、物理过程、概念变化等交互演示 | 小型可交互演示 | 大画布、参数、步骤、演示控制 |

#### 边界

- **阅读、编辑与交付内容或静态结果** → 内容与成果物；

学科能力通过插件式扩展进入统一框架，不为每个学科重新建设一套 Workspace。

## 7. 四项跨组件公共能力

### 7.1 全局任务状态

统一呈现排队、运行、暂停、等待人工、完成、失败、降级和重试等状态，映射既有任务执行契约，不在前端另造一套业务状态真相。

状态可出现在顶部监视器、Agent 消息、固定页面、Workspace 和工作记录中。界面收起不停止后台任务，客户端暂时离线不证明任务失败；状态未知时应明确标注，不猜测成功或失败。

“任务进度”是消费公共状态的语义组件，不是第二套状态管理服务。更新应关联所属任务和执行轮次，不用旧回调覆盖新一轮状态。

### 7.2 历史与版本

重要任务保留必要的历史、版本、修改时间、操作来源和回溯能力。溯源优先说明：谁发起、谁执行、谁确认、修改对象与基准／结果版本、修改内容及执行结果。

不默认要求每个 UI 字段都记录 `ModifiedBy: Agent | User`。评分、正式诊断、发布内容等关键业务数据按既有审计契约保留必要的细粒度差异；界面焦点、折叠状态等不与业务审计混为一谈。

历史信息保留当时事实，不随当前对象更新静默改写。查看旧版本仍受当前权限限制；历史保留不等于永久访问授权。对话历史与实时工作卡的呈现规则见第 10.3 节。

### 7.3 协作

“教育共同体”采用多用户与同一逻辑 Agent 协作，支持成员通信、评论、批注、审核和交接；复用现有任务与组件，不复制一套协作版业务实现。

“同一 Agent”不等于整个平台只允许一个物理进程。应在相应协作任务范围内协调指令、编辑冲突与有副作用的提交，避免多人指挥产生相互覆盖或重复发布。不可用 UI 锁替代受信任执行层的权限与版本检查。

本版冻结“不静默覆盖、不重复产生副作用、责任可追溯”的要求；不统一冻结悲观锁、乐观并发控制或字段／段落锁粒度。具体机制沿用既有对象契约，由工程设计确定。共同参与会话不自动获得所有成员的数据权限。

### 7.4 权限与数据范围

> **所有组件在当前有效授权内读取、呈现和操作数据。Agent、固定页面、导出成果及外部模型调用遵守同一权限边界；界面状态、历史引用、检索命中和模型输出都不能扩大授权。**

| 边界 | 必须遵守的规则 |
|---|---|
| 组织、教师、班级与学生隔离 | 沿用既有身份和数据范围模型，不跨组织、跨教师或跨学生意外混用内容 |
| 授权与任务范围 | 受控业务数据不得超出当前有效授权与本次明确任务范围；未指定范围不等于使用全部授权数据 |
| 来源与目标归属 | 跨班引用、复制或派生，保留来源并明确目标对象与归属；来源授权不自动授予目标发布权限 |
| 权限变化 | 撤销任教、退出组织或切换身份后，后续读取、提交、导出与异步结果交付重新检查权限，不沿用旧界面缓存当作授权 |
| 输出与披露 | 报告、提示、统计摘要、排除明细、附件及外部模型上下文不得泄露无权访问的对象或信息 |
| 协作与共享 | 内容对谁可见、可编辑、可发布分别判定；在同一会话中不代表拥有相同权限 |

组件负责呈现授权结果，不充当最终授权机关。受信任执行层在读取与关键操作时检查当前权限；前端隐藏按钮、客户端筛选、请求携带的范围以及模型判断，都不是可信授权凭据。

恢复草稿、打开历史引用和接收迟到结果时不得绕过权限检查。失权后的可见内容和缓存按既有策略隔离、清理或限制访问，不能在身份切换后重新带出。权限历史保留与当前内容披露分别处理；不得宣称已经导出的离线副本可被界面自动撤销。

## 8. 组件运行逻辑与状态管理

### 8.1 受控任务流

以下是能力之间的依赖关系，不是强制逐卡展示的固定步骤。固定入口可跳过自然语言理解；已有合法参数不重复询问。

```text
自然语言目标 / 固定业务入口
        ↓
定位既有对象与本次任务范围
        ↓
补齐必要输入、参数和约束
        ↓
Runtime 与授权服务校验并编排
        ↓
按需调用规则、内部能力或外部模型／服务
        ↓
返回候选、草稿、执行状态或成果引用
        ↓
组件呈现；必要时由教师查看、修改或审核
        ↓
校验当前权限、基准版本及确认范围后正式执行
        ↓
取得真实回执，更新工作记录与成果关联
```

任务允许在参数、候选和审核之间往返。修改只重做受影响部分，不要求重发整条自然语言请求。范围、评分或发布对象等关键条件变化后，原确认不得被拿来授权新的执行内容。成果回到任务记录，不代表自动进入下一轮模型上下文。

### 8.2 草稿与并发更新

| 情况 | 处理规则 |
|---|---|
| 教师正在编辑，Agent 或后台产生新建议 | 新内容作为候选更新，提示可查看；不得直接覆盖未提交草稿或强制切换当前视图 |
| 提交时正式版本已变化 | 检查基准版本，进入明确的比较、刷新或冲突处理；保留可保留的本地输入，不静默后写覆盖 |
| 两个入口操作同一对象 | 共享权威版本与适用的草稿归属，不分别保存为互相覆盖的正式业务副本 |
| 重复点击或重复回调 | 同一执行请求的副作用不得重复发生；由受信任执行层识别，不能只靠前端禁用按钮 |
| 旧会话或旧执行轮次迟到 | 记录到正确归属；不得替换当前任务、较新成果或已编辑内容 |
| 提交超时或回执不明 | 显示“状态未确认”，查询原请求结果；未核对前不能一面宣称失败、一面重新创建同一副作用 |

本版要求版本条件检查和明确冲突处理，不强制具体锁策略或存储技术。模型建议与人工草稿可比较、采纳或放弃；放弃建议不取消已有正式任务。

### 8.3 离开、恢复与保存

收起面板、切换路由、刷新页面、关闭标签页和切换账号分别考虑。可恢复草稿应由明确的管理方持久化，并区分“已保存草稿”“尚未保存”“已正式提交”；写入失败不能显示为保存成功。

存在尚未可靠保存的修改时，在可拦截的离开操作前提供保存、保留或丢弃选择。浏览器崩溃或强制关闭不保证出现确认框，不能只依赖离开提示承担恢复责任。恢复时核对身份、任务对象、基准版本和当前权限，版本不匹配则进入冲突处理，不自动覆盖正式数据。

不规定所有内容一律写入浏览器长期缓存。敏感作答、成绩及报告的保存位置、保留期限、身份隔离和清理策略复用既有数据要求；没有可靠保存或授权恢复能力时，应清楚说明限制。

### 8.4 撤销、重做与撤回的区别

| 操作 | 边界 |
|---|---|
| 草稿撤销 | 撤销尚未正式提交的编辑，不伪装成正式任务撤回 |
| 重新生成 | 从选定输入或参数产生新候选／版本，保留必要的原结果和变更归属 |
| 失败重试 | 先核对原执行状态，避免已成功但回执丢失导致重复副作用 |
| 已发布任务撤回 | 通过已有业务服务判断是否允许、影响哪些对象、是否需要确认或补偿；不承诺统一的一键回滚 |

不能撤销的动作应明确说明；不能通过改写聊天历史，让已经发生的业务操作看起来没有发生。

## 9. 模型与执行层职责边界

> **本地或外部是部署与调用策略；确定性校验、权限和正式提交是职责边界。两者不能互相替代。**

| 角色 | 职责 | 不允许越过的边界 |
|---|---|---|
| 本地／轻量模型或外部通用模型 | 意图理解、参数抽取、内容生成、建议与判断候选；具体路由按能力、成本和数据策略确定 | 不自行授予权限，不直接把模型输出当作正式业务状态，不宣称未执行的动作已经完成 |
| Runtime | 在既有契约内编排任务、调用能力、处理状态和回执 | 不以编排权限绕过业务对象的授权、版本或人工确认要求 |
| 规则引擎 | 提供确定性约束、规则判定与候选校验 | 不直接写库、提交图谱、修改学习状态、发布题目或形成最终诊断 |
| 受授权业务服务 | 对所属业务对象执行权限与版本检查，完成正式提交、发布和受控状态变化 | 不接受未经核验的组件或模型声明作为授权凭据 |
| UI 组件 | 呈现、编辑草稿、发起受控动作、显示真实状态与成果 | 不因本地渲染成功、动画结束或模型文案而宣称业务完成 |

外部通用模型可按需承担教案、讲解、评语、文档、演示文稿、图像、音频、视频等开放式内容生成；实际生成和格式交付也可能由不同工具或服务分别完成。检索、布置作业、启动批阅等确定性业务操作不因经过自然语言入口就必须调用外部模型。

经感知、模型或规则形成的候选，继续沿用 OLE 既有处理与审核契约；本规范不改变候选到正式业务事实的权限链。

调用外部能力前，只提供当前有权且任务必要的上下文；遵守既有租户边界、数据驻留和模型网关策略。返回结果纳入对应任务与版本关系，并按实际状态呈现“候选”“待审核”“生成失败”或“已取得成果”，不把外部服务响应一概当成正式交付。

## 10. 设计约束

### 10.1 通用约束

**Component ≠ Page。** 组件需能跨业务复用；组卷、批阅、分析是组合场景，不是新的一级组件类型。固定页面与 Agent 复用同一领域能力和业务引用，不维护两套实现。

**渐进式披露。** 默认呈现当前决策所需的信息；已知内容不重复询问，关键权限、证据不足和执行风险不能因追求紧凑而隐藏。

**关键动作由人控制。** 对发布、覆盖、最终提交等高影响动作，确认应绑定明确对象、版本、范围和动作；关键条件变化后重新确认。不得为每个常规可逆步骤增加无意义的确认。

**同一权威业务事实。** 数据、草稿与视图分工遵循第 2.3 节；权限遵循第 7.4 节；执行与冲突处理遵循第 8 节。组件共享不等于所有状态必须塞进一个全局对象。

**数量不等于复杂度。** 42 个语义组件是系统能力目录，不是菜单，不是每次任务的必经流程，也不代表本期必须全部开发。

### 10.2 证据诚实性

> **检索命中、被选中、被预览、被读取、进入本次模型上下文、被某个成果引用，是不同事实。不得根据其中一种推定其他事实。**

读取与引用分别依据可信的执行记录判断，并匹配所属任务／会话、来源、相应版本与执行标识；引用还要指向具体成果版本及定位信息。本机读取不是模型读取，历史读取不证明仍在当前上下文。组件只能呈现记录，不能从检索数量、摘要、模型文案或预览操作“生成”可信证据。

| 证据情况 | 可呈现的状态 |
|---|---|
| 有与目标事实匹配的有效记录 | 已读取或已引用，分别判断；必要时明确“本机读取”“服务执行”及范围，不外推到整份内容 |
| 记录覆盖完整且没有对应事件 | 未读取／未引用 |
| 记录覆盖不完整且没有足以确认目标事实的记录 | 状态未确认 |
| 记录来源暂不可用、无法核验 | 记录暂不可用 |

状态之间不构成可由界面自动推演的进度链。“没有拿到记录”不等于“没有发生”；“已引用”证明引用关系存在，不自动证明结论正确或证据充分。

示例、预置数据和演示流程必须显式标注，不能冒充真实执行证据。读取部分材料时不得声称已完整读取；缺乏当前上下文使用记录时不得声称“已加入上下文”。

本约束适用于上下文摘要、资源检索、下钻与证据浏览、诊断、文档成果、执行结果和工作记录等所有相关组件，不只适用于资源面板。

### 10.3 历史卡片与实时工作卡

历史事实保留当时版本；当前工作卡可以实时更新，但必须明确标识为“当前状态”并关联对应版本。两者共享业务对象引用，不意味着历史叙述可被悄悄改写。

例如：历史消息保留“已生成试卷 v1”；当前工作卡显示“试卷 v3”；一次重要提交后只追加“已替换 2 道题并调整总分”等简短变更摘要，不重复发送整张试卷卡片。

旧卡片上的执行动作必须校验当前权限、版本与请求状态，必要时提示已过期并引导到当前对象，不能重复发布。历史卡片恢复不得绕过失权后的内容限制。

### 10.4 复合呈现

> **语义组件不与消息卡片一一对应。围绕同一决策、同一提交目标的多个组件可以组成一个交互容器；已知或无需人工处理的环节可以不呈现。**

参数与约束可在同一张卡中确认，指标摘要与异常入口可以组合呈现。只有存在先后依赖时才用步骤式；并列信息需要切换时才考虑 Tabs；少量字段可直接展开。不得仅按“超过三个组件”强制套用某种容器。

复合容器不能合并不同权限或目标对象而掩盖影响范围，也不能让一个笼统的“确定”无意触发多项高影响操作。组合仅改变呈现，不改变组件职责与执行授权。

### 10.5 真实能力与受控动作

组件只展示实际支持的查看、编辑、计算、生成和导出能力。生成中的内容、待审核候选、可下载文件与已发布结果分别呈现，不用同一个“完成”标签代替。

模型可提出组件与动作请求，但前端只解析受控注册范围内的组件类型与动作，执行仍通过受信任层校验。未经注册或无法理解的请求应显示安全的不可执行说明，不能执行任意脚本、任意目标或未核验的写入。最小契约语义见附录 A。

## 11. 典型组合示例

以下示例说明如何复用组件，不承诺现有系统已完成端到端业务闭环，也不规定教师必须逐项经历所有组件。已知信息直接带入；可合并、跳过或按需返回。实际操作数、等待时间与效率改善需在第 13 节验证后才可下结论。

### 11.1 组卷

教师：“给高二三班出一份明天 40 分钟的函数单元练习。”

| 工作片段 | 组合能力 | 呈现方式 |
|---|---|---|
| 确认出卷要求 | 范围构建器、模板选择器、参数配置器、约束构建器 | 只把待决定信息组合成一张 Inline 卡，不要求四张卡或四轮对话 |
| 查看与调整试卷 | 候选选择器、集合篮、结构编排器、摘要预览 | 先给摘要；需要认真编辑时进入同一对象的 Workspace |
| 交付试卷 | 执行确认、成果物输出、执行结果 | 明确对象、版本与交付范围，取得真实回执后显示结果 |

三个片段是呈现分组，不是已经验证的“三步完成”承诺。更简单的任务可以更少；遇到异常或教师主动调整时也可以更多。

### 11.2 批阅与解析

文件输入／采集扫描提供材料；任务进度反映实际处理；异常处理器、审核队列和单项复核器只呈现需要人工处理的内容；指标摘要与执行结果汇总已完成工作。

审核时可以从单题返回原始作答或参数，不重建整项任务。成绩、诊断和学生报告的最终提交遵循权限、版本与确认边界；输出文件复用成果物输出，而非另建“批阅导出组件”。

### 11.3 学情分析

对象选择器与范围构建器定位合法数据；指标摘要、分布矩阵及下钻与证据浏览形成可解释结果；建议集、计划构建器将结果转为教学行动。

教师可以停在指标摘要，也可以进入 Workspace 深入分析；不是每次都必须生成学习计划。学生报告不得带出其他学生的排除信息或无权访问的明细；没有足够证据时明确标注。

### 11.4 为《火烧云》准备教学素材

范围构建器定位课程；资源检索器寻找相关素材；素材提取器按需提取片段；素材包组织可复用资源；图像、视频或文档工作区负责查看和加工。

只有教师需要课件或文件交付时，再组合演示文稿工作区与成果物输出。检索命中不等于已经读取或引用；来源、可用性与必要的使用限制应保留。

### 11.5 为学生演示圆的性质

范围构建器明确目标；资源检索器可选；交互演示器或学科专用编辑器承载几何关系与参数变化；结构化内容工作区可组织演示讲解。演示文稿工作区与成果物输出仅在需要时组合。

交互模型与静态截图分别标识。手机端按可可靠支持的操作提供浏览、参数控制或轻量批注；无法可靠完成的复杂作图明确引导桌面接续，不宣称能力等同。

## 12. 分类归属与后续扩展规则

### 12.1 归属优先级

十二类按主要交互职责组织，不按某一次任务恰好处于哪个步骤归类。

> **主要交互职责 → 维护的对象或结构 → 所需专用编辑能力。**

业务阶段、学科、格式、入口和设备是辅助描述，不单独决定一级归属。一个组件可以被多个阶段、页面和学科使用；复合场景可以组合不同族的组件，不必强行归入单一族。

| 容易混淆的边界 | 判定方式 |
|---|---|
| 范围构建器／约束构建器 | 前者确定参与对象集合；后者约束执行方式或结果条件 |
| 执行结果／成果物输出 | 前者报告执行事实；后者负责格式、版式与文件交付，允许组合 |
| 教学资源／内容成果物 | 前者检索、提取、组织素材；后者阅读、编辑、交付内容，同一资产可先后承担两种用途 |
| 通用图形工作区／学科工具 | 通用结构编辑归内容成果物；引入学科计算、约束与模拟时，由学科工具承担 |

### 12.2 扩展顺序

先检查既有组件能否复用、组合或通过适配器支持；确有不可覆盖的稳定交互职责，再在现有族内新增语义组件。发现缺口不推翻既有分类，也不为相似名称重复建组件。

只有在新职责不能合理归属十二类、具有长期跨业务价值、强行归类会污染职责且有多个真实场景需要时，才讨论增加组件族。格式变化、移动端布局或一个新的业务页面，本身不足以构成新增组件的理由。

新增或修改遵循既有 Review 与版本管理要求。组件能力目录的扩展不自动扩大本期交付范围。

**本节只登记待验证事项；本次批准与文档修订不启动真实教师任务验证、代码测试、模型试验或站点实施。**

后续恢复验证时，仍优先覆盖组卷、批阅与解析、学情分析、教学资源准备、文档／PPT 成果生成和学科工具六类场景。先验证差异最大的真实任务，不按 42 个组件机械分配同等测试工作量。

| 待验证路径 | 必须核对的结果 |
|---|---|
| Agent 与固定入口往返 | 对象、权威版本、草稿和权限不分叉；已知信息不重复填写 |
| 跨班派生与目标归属 | 来源保持可追溯，目标归属明确；不误写原班成果，不扩大授权 |
| 撤销任教后恢复、提交或收取异步结果 | 重新检查当前权限；旧卡片、缓存或在途请求不能绕过边界 |
| 学生报告与输出文件 | 不带出其他学生的排除信息、明细或不可见对象信息 |
| 无证据、部分证据、记录不可用、旧版本引用 | 准确区分未读取、未引用、状态未确认和记录暂不可用；不伪造模型上下文使用 |
| 深度编辑中收到 Agent／后台更新 | 不覆盖未提交草稿，不抢焦点；版本冲突明确处理 |
| 刷新、切换入口、关闭或保存失败 | 草稿保存状态真实，恢复有身份与版本检查；失败不伪装成成功 |
| 旧 Inline 动作、重复点击、迟到或重复回调 | 不重复产生副作用，不污染其他任务或新版本 |
| 历史与当前工作卡 | 当时事实不被改写，重要变化可追踪，当前状态清晰且不反复刷整卡 |
| 组卷等多组件组合 | 语义组件不逐项刷屏，不因组合隐藏关键条件或扩大确认范围 |
| 紧凑试题篮隐藏对话、全区阅卷、退出专注模式 | 教师知道任务与状态、保存情况及返回位置；返回后对象和草稿保留 |
| 窄容器、文字放大与触控编辑 | 工具栏和返回入口可达；拖拽有适当替代；能力限制明确，不能只检验有无横向溢出 |
| 外部服务不可用、格式能力不支持或转换有损 | 如实标注失败、限制与交付情况；不生成虚假下载链接或假称已完成 |
| 修改后重做、重试与已发布任务撤回 | 只重做必要部分；重试核对原执行，撤回遵循业务服务与影响范围 |

效率对照必须在相同目标、数据、结果质量及必要审核条件下比较传统固定流程与 Agent 流程，记录教师主动操作、必须决策、重复输入、等待／返工和任务完成情况。不能仅数点击，也不能靠省略复核制造效率提升。验证前不宣称已经减少多少步骤、延迟或成本。

实现层锁策略、草稿存储方案、具体布局断点及各组件支持范围，沿用已有设计或在恢复实施时确定；本次不把这些未决技术选择默认为已冻结实现。

## 14. 修订基线摘要

**OLE Teacher Workspace Agent Component System v0.2.1 — Approved**

十二类、42 个语义组件保持不变；体系支持 Inline 与 Workspace 两种呈现方式，各组件按需要声明。84 只是理论覆盖组合数，不要求 84 套独立界面，不代表本期研发规模。

四项公共能力为：全局任务状态、历史与版本、协作、权限与数据范围。证据诚实性是所有相关组件的一级约束，不另建组件族。

Agent 与固定页面复用同一权威业务对象、适用草稿和组件能力；允许独立视图状态与历史快照。并排和专注全区属于布局变化；移动端同时考虑布局与能力适配，不新增第三态。

复合呈现减少无意义卡片和重复决策；模型输出仍是候选或请求，Runtime 与受授权服务掌握执行和正式提交边界。格式通过适配器支持，不强制统一内容 AST，不承诺本期自研所有编辑器。

后续优先复用和组合，确有缺口再在现有族内新增。v0.2 原件保留；本版修订已获批准，但不代表实现完成、测试通过或效率已验证。真实任务验证继续暂停。

## 附录 A. 最小组件调用契约语义

本附录连接现有 UI、任务与业务契约，不建立新的权威任务对象，不代替 OLE 既有对象、版本和权限模型。以下冻结必要语义与行为要求，**不冻结新的字段名、接口名、JSON Schema 或通用 `TaskSessionSchema`**；实施时先映射到现有契约，确实缺失才按既有治理流程补充。

| 必要语义 | 要求 |
|---|---|
| 组件身份 | 可识别受控注册的组件类型及契约版本；不支持的类型或版本不得直接执行 |
| 业务关联 | 引用既有任务／业务对象、所属会话或执行归属，以及适用的对象版本；不拷贝为新权威对象 |
| 呈现与能力 | 声明 Inline／Workspace 的支持范围及查看、编辑、提交、导出等实际能力；布局偏好不得覆盖宿主空间和教师当前操作 |
| 状态来源 | 区分当前权威版本、编辑草稿和历史快照；适用时携带基准版本及可信状态引用 |
| 可用动作 | 使用受控动作标识与类型化参数，声明目标和影响范围；可见动作列表不等于授权凭据 |
| 请求关联 | 对执行请求关联所属任务、执行轮次和可识别重复请求的信息；关联标识不能赋予越权能力 |
| 回执与错误 | 区分已接收、运行中、待人工、成功、失败和状态未确认，按既有状态契约映射；实际完成必须有可信回执 |
| 权限与证据 | 引用可核验的范围、授权结果及必要证据；前端或模型填写的范围和“已读取”标签不能充当可信事实 |

宿主根据注册信息、实际空间及用户操作决定呈现；受信任执行层重新核验当前权限、对象版本、合法动作和必要确认。未知动作、过期请求、失权或冲突不得以静默降级方式继续写入。

本附录不要求新增四份独立规格，不强制统一内容中间态、全部字段级审计、统一编辑锁或固定分屏尺寸。具体适配器、持久化与并发实现仍复用已有能力，并与变更影响相称。
