# 题目呈现章程 v0.1

状态：Product Owner 于 2026-09-28 确认（“对话里不就地展开详情，而是统一去右栏看，就这么整”）。

适用于智能曜彩题目组件与 Agent 中所有题目相关组件。配图：设计稿《Agent 组件高保真 · 第一批》画板“题目层级 / 展开形式 / 详情展开 / 题目卡 / 手机详情 / 题目呈现章程”（https://claude.ai/artifact/QGmje6CMDyAJZpVH1V6nja）。规范权威顺序中位于第 3 级（Pattern 与组件复用约定），不得覆盖 Agent 组件规范 v0.2.1 与 Foundations。

## 第一条 适用范围

1. Prism 题目组件：QuestionCard、QuestionContent、QuestionDetails、QuestionActions。
2. 呈现题目的 Agent 组件：06 内容输入、10 候选选择器、11 集合篮、12 结构编排器、14 对象查看器、15 对比查看器、16 审核队列、17 单项复核、19 指标摘要、20 分布矩阵、21 下钻与证据、33 成果物输出、42 学科专用编辑器。
3. Workspace 中组卷、批阅、学情页与 Agent 工作区里所有出现题目的位置。

## 第二条 单一来源

1. 题面、选项、小问与公式只由 QuestionContent 渲染；详情只由 QuestionDetails 渲染。
2. Agent 组件不自绘题面、不自拼“答案：… / 解析：…”；题目内容一律经宿主插槽（renderItem 等）传入，组件只负责外层结构与状态。
3. 同一道题在同一屏只有一个可交互实例；其他位置用 L0 引用指向它。

## 第三条 四个呈现层级

1. L0 引用：题号 · 标题（可带一个状态），点开进入 L2。用于正文、过程行、审核队列、指标、分布与证据。
2. L1 摘要行：题号 · 标题 · 属性一行 + 题干（完整或节选）；无外框，嵌在 Agent 卡片内。用于候选（对话态）、题篮、编排、变更列表。
3. L2 题目卡：完整题面与操作，带详情。用于右栏扩展态、组卷与题库页、单题查看、复核。
4. L3 阅读 / 打印：无外框、无操作，只有题号、题面、分值。用于正式试卷、打印预览、只读回看。

## 第四条 组件与层级对照

1. 对话态：10 → L1；11 → L1；12 → L1；16 / 19 / 20 / 21 → L0；33 → L3。
2. 扩展态（右栏）：10 → L2；14 → L2（详情默认展开）；15 → L2 片段 + 差异；17 → L2 题面 + 差异，详情只含“答案与解析”；42 编辑区下方预览用 L2 题面。
3. 专业页：组卷与题库 → L2；正式试卷与打印 → L3；批阅与学情中的题目引用 → L0，点开为 L2。

## 第五条 详情内容

1. 三个页签，顺序固定：答案与解析 → 教学定位 → 题目档案。
2. 未关联的字段写“未关联 / 尚未关联教材章节”，不隐藏；不在页签外散落答案、知识点或来源。
3. 页签可由宿主按场景裁剪（如作答、考试场景隐藏答案；复核只给答案与解析），裁剪由宿主传入，组件不自行判断。

## 第六条 详情的展开形式

1. A 专业页：卡片内展开，详情为卡片内浅灰容器；同一列表同一时间只展开一题；展开后保持该题在视口内。
2. B Agent 对话中：题目只以 L1 / L0 出现，不在对话内展开详情；“在右栏查看”打开右栏 L2，默认停在“答案与解析”，对话位置不动。
3. C Agent 右栏：L2 详情默认展开；上一题 / 下一题在右栏标题行切换并保留所选页签；关闭右栏焦点回到触发的那一行。
4. D 手机（< 600）：右栏变为全屏页；顶部返回对话，底部“上一题”与主操作各 44px。

**文案修订（2026-09-29，PO 批准）**：B 类对话中打开右栏 L2 的操作文案为‘查看详情’，以明显按钮呈现；行为不变。

## 第七条 视觉

1. 外框：L2 与 Agent 普通卡片同一表面（1px 描边环 + shadow-xs/5，圆角 12）；勾选后描边为 primary 60%。
2. 标题行：“第 n 题 · 标题”14/20/600；题型 · 分值 · 难度为一行 12/18 弱化文字，不画框——框和底色只留给状态。
3. 题面：题干与选项 16/28，公式不缩小；选项在容器 ≥ 480 时两栏，否则一栏。
4. 操作：左侧“详情”与次要操作，右侧一个主操作；其余进入“更多”。
5. 详情区：卡片内 secondary 底浅灰容器，下划线页签。三主题只用现有语义令牌。

## 第八条 诚实与标识

1. L1 题干被截断时必须显示“节选”，并能一步打开完整题目（Agent 规范：不得声称已完整读取）。
2. 示例题目显示“示例”；题目档案显示真实题目编号，展示用的“第 n 题”只放在标题行，不写入编号字段。
3. 答案是否可见由宿主决定并显式传入；组件不因“已作答 / 已提交”等状态自行显示答案。

**原型阶段修订（2026-09-28，PO 批准）**：仅适用于未接入真实服务、全部为本机规则与预置数据的原型阶段。此阶段 Workspace 界面不逐项标注“示例／预置／演示”，组件保留 `visual.sample`、示例小签等标注能力，由 Workspace 停止传入相应标注属性。接入真实服务或混入真实数据后，恢复逐项标注；真实与示例混排时必须标注。本修订仅调整原型标注策略，不改变读取、引用、保存、提交等事实及状态的判定，不免除“节选”标记。原条文保留，恢复条件满足后继续适用。

## 第九条 交互与可达性

1. 主操作文案统一为“加入试题篮 / 移出试题篮”；勾选框的读屏名包含题号与标题。
2. “详情”按钮带 aria-expanded 与 aria-controls；页签键盘可切换；右栏与全屏页关闭后焦点返回。
3. 触控目标 ≥ 44px（手机）；公式与长中文不裁切，必要时局部横向滚动。

## 第十条 实施与验收

1. 一、Prism：QuestionCard 按第七条统一视觉；在现有 compact 基础上定义 L1（含节选标记）与 L0 引用；不新增组件目录条目，不改 coss。
2. 二、Prism：10 / 11 / 12 / 14 / 15 / 17 按第四条改为通过插槽使用题目组件，示例同步。
3. 三、Workspace：右栏单题查看改用 QuestionDetails；去掉用“第 n 题”冒充题目编号的写法；候选、题篮、编排按层级接入。
4. 四、验收：三主题 × 1280 / 900 / 390 / 320；长中文、公式、多小问；键盘与焦点返回；对照本章程逐条记录。
