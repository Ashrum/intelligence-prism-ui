## 2. 分工与复用顺序

| 责任方 | 负责什么 | 本轮边界 |
| --- | --- | --- |
| 智能曜彩 | 组件语义、信息层级、交互、状态呈现、可访问性、主题、能力说明、受控输入与事件、最小组合示例 | 不创建完整教师业务页面，不持有业务存储，不判断最终权限，不执行 Runtime |
| Workspace | 当前宿主约束、业务对象及版本引用、草稿管理、路由、会话与题篮数据源、工作区布局、后续接入适配 | 提供真实使用条件；不另做一套外观近似而接口分叉的组件 |
| Runtime 与受授权业务服务 | 权限和版本校验、业务规则、执行、幂等、可信回执、读取及引用记录 | 组件接收可呈现结果并发出请求，不替代这些职责 |

复用顺序为：**现有组件 → 现有组件组合或公开属性扩展 → 抽取 Workspace 的通用部分 → 确有稳定缺口才新增。** 新增前继续核对固定来源的 coss 和相关 particles；本规划未提出另造按钮、表单、浮层、树或图表基础库。

“Agent 语义”说明组件在任务中承担的交互职责，不要求所有组件改名为 Agent 开头，也不要求固定页面经过模型才能使用。一个实现可以覆盖多个语义，一个语义也可以由多个既有组件组合。

## 4. 第一批设计：六项语义与呈现方式

六项共同解决“我在处理什么、需要决定什么、执行到哪里、得到什么、能否继续修改”。第一组已具备可评审的候选呈现（§1.1）；下表保留设计方向，下一步验证两态连续性，不按名称拆成六个代码包。

| 语义 | Inline 呈现方向 | 确需展开时 | 首轮重点 |
| --- | --- | --- | --- |
| 上下文摘要 | 对象、范围与关键约束的短摘要；来源按需展开，必要的不确定性直接可见 | 同源完整来源列表、范围说明与证据定位 | “选用”不表示“读取”；本机读取、模型上下文使用和成果引用分别表达 |
| 摘要预览 | 成果名称、版本、当前内容状态、简短摘要及可用动作 | 交给宿主打开已有对象查看器／编辑器 | 未提供有效查看能力时不显示假展开入口；历史和当前对象明确区分 |
| 对比查看器 | 少量关键差异和明确的采纳范围 | 完整差异列表或领域渲染器；窄容器顺序阅读 | 不隐藏决定所需内容；外部草稿冲突可见；不能把采纳候选当正式提交 |
| 执行确认 | 动作、目标、版本、影响与关键条件放在一个决定区 | 仅复杂影响范围或参数需要详情，不为简单确认建空工作区 | 常规低影响操作不重复确认；关键条件变更后旧确认不继续授权 |
| 任务进度 | 当前阶段、等待原因或阻塞项；数量仅在可信时呈现 | 同一执行的阶段明细、异常和宿主提供的恢复入口 | 对话回复结束不等于任务完成；缺回执时显示状态未确认 |
| 执行结果 | 已完成与未完成事项、结果版本及实际可用的下一步 | 同源回执明细、成果清单与必要的失败信息 | 有成果不等于已发布；执行状态不明时先请求查询原执行结果 |

支持范围按组件声明：上下文、比较、进度和结果可以有摘要与详情；摘要预览主要是 Inline 与对象打开入口；执行确认通常在当前决定区完成。详情可以复用通用扩展容器，不要求每项独立实现 Workspace。

### 信息与视觉原则

- 先呈现当前决定所需的信息；名称、状态、关键内容、操作形成清楚的阅读顺序。历史／版本／证据身份在会影响判断时保持可见。
- 同一决定、同一提交目标允许组合多个语义。参数与约束可以共用确认区，结果与成果摘要可以组合，不按目录逐张刷卡。
- 行、列表、表格、展开区与卡片按内容选用；不把所有消息套成相同卡片。并列内容才考虑 Tabs，有先后依赖才使用步骤。
- 每个操作区域保持一个主要动作，其他动作使用既有层级。沿用 coss / Prism 的尺寸、焦点、键盘与浮层行为。
- 沿用三主题和语义令牌；三色服务状态与意图，不装饰每个容器。状态同时有文字或图形，不只靠颜色判断。
- 遵循现行 Typography：题干、完整回复、长编辑区用阅读角色，决策说明和状态使用至少 14px 的相应角色；空间不足换行、展开或调整布局，不缩字。
- 通过比例、留白、对齐和清楚的操作位置提高品质；不新增图标底板、发光、重阴影或重复分隔线。
- 动效只解释用户操作和外部状态变化，尊重减少动态效果；动画结束不能作为业务完成条件。

具体尺寸、断点、色值和新属性名留到设计阶段依据现有契约核对，本规划不另造视觉 Token。

## 6. 两态承载层

### 6.1 问题与定位

v0.2.1 §4.1（L115–119）把展开、缩放、关闭及对象／题篮切换交给工作台视图管理。Workspace 已有本地实现：`WorkspaceObjectHeader`（AgentWorkspace.tsx L50–57）、`WorkspacePanels`（L62–195）、单一右侧区（L149–164）、专注与滚动记忆（L59、L107–146）；视图 reducer 保存／恢复专注前布局（workspace-model.ts L104–129），焦点返回由 use-workspace.ts L49–102 处理。本次只确认源码存在，不宣称这些路径已通过交互验收。

智能曜彩 `AgentPageSkeleton`（`23a112c:components/prism-next/skeletons/agent-page.tsx` L10–26）的主体只有消息滚动区与输入区，另有对话标题、操作及提示插槽；没有右侧对象工作区与对象头。`WorkbenchShell`（同目录 workbench-shell.tsx L24–40、L132–152）虽提供 context、auxiliary 与内容插槽，但辅助区收纳并不提供同一对象的并排／专注、草稿保存状态和返回协议。因此原规划第 8 节验收第 3 条“两态连续”、第 7 条“宿主可接”（现第 11 节）尚不能在本仓库现有骨架中演示完成。

**两态承载层属于页面骨架，由 AgentPageSkeleton / WorkbenchShell 组合提供。** 不计入 80 项组件目录，不新增第 43 项语义；并排与专注全区属于扩展态的布局变化，不是第三态（v0.2.1 §2.2 L53–57、§4.1 L115–119）。本节登记待设计职责，不宣称已有可直接迁入的完整骨架。

### 6.2 职责划分

| 层级 | 提供或保留的职责 | 明确边界 |
| --- | --- | --- |
| 页面骨架 | 单一右侧工作区；并排与专注全区布局切换；通用对象头呈现对象身份／版本、宿主传入的草稿保存状态〔未保存／已保存草稿／已提交／冲突／状态未确认〕；提供返回对话、放大／还原、收起的受控操作呈现及焦点、阅读位置接续机制 | 可复用纯布局与操作呈现；不自行推定保存成功，不创建业务草稿、不请求业务取数 |
| Workspace 宿主 | useAgentWorkspace、disclosure reducer、请求归属与防抢占、全局题篮 Provider、会话存储、业务对象取数、业务草稿及保存／提交管理 | 决定当前对象和可见性，提供可信状态与意图回调；服务器权限、版本及回执校验继续交受信任层 |

通用对象头与布局工具由骨架统一组合；宿主已在唯一工具栏呈现返回或放大／收起时，对象头只展示身份、版本与状态，不再重复放按钮。当前 Workspace 新页已经使用 `controls={false}`（AgentWorkspacePage.tsx L490–506），工具栏在 L682–712；此处理与宿主 §23–24 一致。现有对象头只接收 title/description，**五类草稿保存状态的通用呈现是待补设计要求**，不能从该源码推定已具备。

收起≠丢弃／提交／取消，专注≠新建草稿。视图布局变化只作用于当前对象，题篮与对象切换共用一个右侧容器；后台请求不得抢占用户编辑或重开已关闭的同一请求。夹具可由外部受控数据演示这些边界，不复制 Workspace 的业务控制器。

### 6.3 从 Workspace 抽取的边界

按本仓库 [AGENTS.md §1、§5](../AGENTS.md)，可抽取对象头的信息组织、受控按钮、单容器布局以及通用焦点／滚动接续机制；不得直接复制含 useTeacherStore、题篮 Provider、useAgentWorkspace 的 WorkspacePanels。抽取前拆开纯呈现与业务依赖，运行时代码不引入 Workspace 私有类型。

业务 Hook、Store、路由、会话持久化、请求归属和防抢占仍留在宿主。源码中的 sessionStorage 与内存 Map 只能说明现有前端策略，不证明可靠草稿恢复、身份隔离或跨刷新执行幂等。公共骨架的参数形状、布局断点及状态接续方式在设计阶段核对既有契约，本版不冻结。

## 9. 组件输入、事件与四项公共能力

先把 v0.2.1 附录 A 的语义映射到现有输入和回调。下表是**规范责任分配／未来接入要求，不是 Workspace 已完成功能清单**，不冻结新字段、JSON Schema、统一 TaskSession 或新的权威对象。当前 owner/requestId/handled 保护只是前端显示和当前挂载期的请求处理，不等于跨刷新去重、执行幂等、身份隔离或服务器恢复。

| 输入或事件 | 组件处理 | 宿主／受信任层处理 |
| --- | --- | --- |
| 业务对象、版本、任务／会话归属 | 显示对象身份，按引用发出打开请求 | 解析引用、取数、检查当前可见范围 |
| 草稿、基准版本、保存状态 | 受控编辑，显示未保存／已保存草稿／已提交／冲突／状态未确认；发出变更意图 | 管理共享草稿、持久化、恢复、版本冲突与提交 |
| 呈现支持和实际能力 | 只展示已支持的查看、编辑、导出等操作；适配容器 | 选择承载布局、内容适配器和当前入口；决定服务能力是否可用 |
| 动作与确认范围 | 显示意图、目标、影响和当前有效性；发出已注册动作事件 | 验证类型化参数、权限、版本、确认范围与幂等后执行 |
| 回执、错误、更新归属 | 区分已接收、运行、待人工、成功、失败和未知；不根据点击推定成功 | 关联实际执行轮次、核对原请求、决定重试／撤回是否允许 |
| 来源与证据结果 | 显示可核验事实与未知／暂不可用；保留必要定位和版本说明 | 提供可信读取、引用和上下文使用记录及覆盖情况 |
| 权限／能力变化 | 接收宿主给出的可见内容与可用动作，显示允许披露的原因 | 在读写与异步交付时重新授权；处理缓存和敏感内容清理 |

组件可维护展开、悬停、暂时选中等局部视图状态；凡要求跨 Inline、扩展态和固定入口连续的草稿与业务选择，使用宿主控制。输入格式和可访问性校验可以留在组件，业务规则与授权不能移入。

不设计任意组件脚本执行器或通用 Agent Runtime。未知组件／契约版本／动作显示不可执行说明，宿主使用受控注册映射；原始模型输出不能直接变成可执行回调、任意目标或写入请求。

四项公共能力作为共享呈现约定接入，不另建四套管理系统：

| 公共能力 | 本批组件侧覆盖 |
| --- | --- |
| 全局任务状态 | 消费既有执行状态与更新时间；步骤明细不另造任务事实；离线／过期与失败分开 |
| 历史与版本 | 区分历史快照、当前状态、编辑草稿；旧动作过期有明确反馈；重要变化追加简短摘要 |
| 协作 | 按宿主提供的责任人、候选变更和冲突结果呈现；不建设成员通信、锁服务或多 Agent 编排 |
| 权限与数据范围 | 显示当前合法范围、只读／不可用和授权变更结果；组件隐藏不当作最终权限判断 |

## 11. 设计验收标准

1. **跨场景成立。** 用同一个实现和两组不同的数据／动作证明复用，例如解析材料与备课资源、任务结果与文件成果；不复制一个完整页面来凑第二个场景。
2. **范围清楚。** 组件不导入教师业务 Store、业务 Router、Runtime 或授权实现，不包含业务 localStorage；fixtures 与正式组件分开。
3. **两态连续。** 用最小受控宿主夹具展示同一对象和草稿；展开、收起、专注恢复不重填、不丢输入、不触发提交。这里只验证组件适配，不宣称真实任务闭环完成。
4. **状态诚实。** 覆盖与组件相关的加载、空态、失败、未知、只读、过期与冲突；读取不推定引用，来源不可用不推定未发生，回执未知不直接提供无条件重试。
5. **历史不被改写。** 同一对象的历史快照与实时工作内容分别呈现；旧卡片动作不能伪装成当前有效动作。
6. **信息足够。** Inline 不隐藏决定所需的范围、证据不足和影响；一个模糊“确定”不能代替多个目标或多项高影响操作。
7. **宿主可接。** 单一右栏和统一工具栏适配成立，不增加并行浮层控制器；用户主动编辑和关闭得到尊重。
8. **视觉与可用性同时成立。** 实看三主题、长中文、公式、窄容器、文字放大、键盘与触控等效操作；既检查阅读主次、密度、留白和操作距离，也检查焦点、换行和滚动。仅“无溢出”不算通过。
9. **验证与影响相称。** 后续仅对实际修改的状态、动作边界和宿主适配做必要组件测试与视觉核对；不为轻微可逆样式变更编写镜像测试，也不在本轮启动暂停中的真实教师任务验证。

设计通过、实现完成、组件测试通过和业务接入验收分别标记。权限撤销、真实幂等、并发提交、持久化恢复与 Runtime 回执等留给 Workspace 和受信任服务联调，不能用演示夹具替代。

## 附录 D. 执行确认＋任务进度＋执行结果的最小组合

这是同一目标、同一执行的呈现设计参照，不是完整业务流程或新增 Runtime。组件页用手动、明确标注的示例回执演示；实际优先级仍消费宿主可信状态。

固定阅读顺序为：对象／版本／范围 → 当前阻碍或待决定事项 → 必要进度 → 结果与下一步。等待确认时确认区在上；提交被接收后收为只读确认摘要；结果到达后以结果为主要内容，过程按需展开。历史事实追加而不改写，不在消息里连续堆三张重复大卡。

| 外部事实 | 确认区 | 进度区 | 结果区／主动作 |
| --- | --- | --- | --- |
| 条件齐备、待确认 | 展示目标与影响，允许明确确认 | 尚未开始，不显示虚假百分比 | 不显示完成结果 |
| 请求已接收／运行中 | 只读保留本次确认范围，不能重复提交 | 当前阶段与可信数量 | 可查看；停止能力由宿主声明 |
| 待人工处理 | 当前决定优先；说明它属于原任务的哪一处 | 保留已有阶段，明确等待原因 | 完成必要决定后再请求继续，不自动新建任务 |
| 提交前版本变化或失权 | 阻断区优先于确认按钮 | 不假称本次已经执行 | 查看当前版本或返回；重新取得合法条件后再确认 |
| 提交后回执不明 | 不再次提供原提交主动作 | 显示“状态未确认”，不擅自标失败 | “查询原执行结果”优先；不无条件重试 |
| 完成／部分完成 | 历史确认摘要 | 过程收起但可查看 | 列出完成与未完成范围、结果版本；只提供真实可用动作 |
| 明确失败且允许恢复 | 显示宿主提供的限制或条件 | 失败阶段和已完成部分保持可查 | 有可信失败和恢复许可才提供受控重试／修订 |

多种情况同时出现时：**先执行宿主给出的访问限制，再突出阻碍当前决定的错误／冲突／待人工事项，再显示运行进度，最后呈现结果与历史。** 权限被收回时不能为了保留历史而继续暴露受限内容；部分失败不能把成功部分涂成全失败。示意用的前端状态不能代替服务端状态模型。
